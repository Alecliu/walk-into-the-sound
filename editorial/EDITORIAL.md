# 走到那首歌｜編輯方式

2026-10-03 使用者確認：以音樂部落格呈現，分類改為標籤；其後將每日一篇提高為五篇，增加 MV 場景、日韓歌手與團體、製作人及新歌篇幅。五篇配額從 2026-10-04 起生效，台北時間 09:00 開始發布。每日更新的操作與限制見 [DAILY-PUBLISH.md](DAILY-PUBLISH.md)。

## 聲音

像一位喜歡音樂、願意查資料並留下筆記的作者。好奇要落在具體問題：誰做了這段編曲、哪個版本先發行、訪談怎麼說、資料為什麼互相矛盾。可以表達選題判斷，但要說得出理由。

直接寫發現，保留有趣細節。不要把每件物品寫成會說話，不替創作者補內心獨白，不用「那一刻」「重新被聽見」「靈魂」「回家的方向」替代事件。也不把文章寫成查證免責聲明的集合。少用抽象結語，停在值得比較的作品、版本或下一條資料。

不捏造作者的親身經驗：沒有實際聆聽或到訪，就不寫「我第一次在那間店聽見」「重聽後發現」。創作者自述要標明是訪談說法；評論和聆聽建議不要冒充事實。

每篇使用已安裝的 `humanizer-zh`，先讀 SKILL.md，保留事實、專有名詞、年份、引文、連結與不確定性。以繁體中文完成終稿。既有文章的文字修訂記 `editedAt`；只有重新查閱事實來源才改 `reviewedAt`。

## 選題

所有文章在同一份依日期排序的列表，用 `topics` 多標籤篩選；舊 `lens` 保留相容性。原有四個標籤是影像與配樂、歌詞裡的地方、唱片與物件、現場與相遇，新歌觀察與音樂人筆記也在同一份列表。

每天預留兩篇新歌／近期作品、一篇 MV 場景、一篇製作人或錄音幕後、一篇音樂人故事。兩篇新歌以近 60 天正式發行的作品為範圍，核對作品版本與發行日期；新聞或影片重上傳日期不能代替發行日。日韓題材分配在新歌與人物欄位，每天交換順序；其餘題材不限音樂場景，網站不建立國家分類。MV 場景與製作人也可以寫新作品，讓當期作品有足夠篇幅。

新歌榜單和潛力雷達是線索；要再閱讀訪談、作品介紹、官方錄音／演出紀錄，才寫成文章。不能照抄榜單清單，也不能把排名上升推論成必定爆紅、未簽約或可合作。排行榜只引用有日期、平台、榜名與可閱讀來源的數字；舊快照不稱為今天。有可靠增量或名次資料才談熱度變化，沒有數據就寫作品觀察，不憑感覺宣稱正在爆紅。

MV 地點須由製作紀錄、導演訪談、場館等資料確認；分清實景、片廠與虛構場景。製作人、詞曲作者、編曲及錄音師分別核對職務，從具體作品與合作切入，不把團隊工作全部歸功一人。日韓歌手與團體可寫成員合作、創作轉折與歌曲細節，不以人物履歷或粉絲宣傳稿取代故事。

每天以五篇為目標、最多補到五篇（人工當天發表也計入），不重寫既有文章、不改程式、不補發過去缺額。先看已發表題目、作品與今天已完成的稿件，避開同一首作品以及最近三天相同主要音樂人。逐篇研究、使用 humanizer、重新校閱；一篇失敗不牽連其他通過稿件。缺額保持缺額，不拿舊文改日期或把不合方向的稿件塞入新歌欄位。

## 證據與素材

至少兩份實際讀到的資料，優先第一手訪談、官方作品資料、場館或檔案紀錄；可對照報刊、可靠部落格、Wikipedia。每個關鍵事實附可點擊來源；無法打開的全文、搜尋摘要、未看過的影音不能寫成已讀來源。來源有分歧保留分歧。少量轉述，避免長篇翻譯或複製完整歌詞。

地理資訊用城市、街區、地點；只有城市被確認就只標城市。非地理選題可留空，不虛構地點來滿足版型。不要以國家分類。

每日自動文章預設不用新照片，避免誤用宣傳照或封面。日後加入照片，必須確認免費使用授權，保存作者、來源、授權；現有照片資訊完整保留。歌曲直接 YouTube 連結要能確認影片與發布者，否則使用清楚標示的「YouTube 搜尋」。

## 發布

文章資料在 `src/data.json`，研究摘要在 `editorial/daily/`。所有原文、來源與固定欄位先校驗，再依 Data 外掛正式流程重建完整 `site/`。通過程式測試、快照／HTML 雜湊與資料一致性檢查，才推送原儲存庫 `main`；等 GitHub Actions 成功並驗證正式網站資料，才算發布完成。
