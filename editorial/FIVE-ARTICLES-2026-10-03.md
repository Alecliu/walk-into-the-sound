# 每日五篇與選題更新

2026-10-03 使用者將每天一篇提高為五篇，並要求增加 MV 場景、日韓歌手／團體、製作人與歌曲背後的故事，新歌需有足夠篇幅。自下一次日更 2026-10-04 套用，09:00 開始發布不變，備稿提前到 05:00。

## 實作

- 五個獨立欄位：新歌兩篇、MV 場景、製作人、音樂人故事。日韓方向分配在新歌與人物欄位，逐日交換。仍使用主題標籤與城市地點，不建立國家分類。
- 新歌檢查實際已發行日期（60 天內）、引用來源與主題；校閱另核對發行版本、指派方向與事實。流量數據必須有當期來源與統計口徑，不能拿過時快照當現在趨勢。
- 每篇獨立保存與校閱；重跑保留已完成稿件，只處理缺額。重複作品、近三天主要音樂人、過期稿、重複欄位與每日超額均阻擋。人工當日文章也計入五篇上限。
- 09:00 已有部分通過稿時先發布；後續重試補查缺額。睡眠／登入後備稿若已過 09:00，完成後接續發布；跨日不沿用前一天日期。
- 保留原單篇來源紀錄，新增來源紀錄按日期與欄位分檔。不更動網站版型、原文章、保護 runtime 或發布位置。

## 驗證

Python 22 項通過，包含五篇配額、部分成功續跑、來源失敗隔離、新歌日期與來源、跨稿重複、每日欄位與舊網址保留。Node 28 項通過。

在私人隔離 checkout 以五篇明確標記的測試稿演練完整流程：合併五篇、官方 Data 外掛 build --separate-data、校驗圖片、更新完整 site、全部測試、來源／成品雜湊、暫存區白名單。dry-run 成功，未 commit 或 push；測試稿與模擬日期沒有寫入開發目錄或正式站。演練亦修正測試依賴「當天還沒有文章」的假設。

正式站資料仍是既有 21 篇，verify-site 通過；本次只改排程程式、選題規則、測試與操作文件。明日真正的網路研究與模型校閱尚未執行；來源、額度或登入失敗仍會阻止相關稿件發布。
